Connect to Drizzle Studio

Drizzle Studio is a full editor for the live database. It runs on the server and is never open to the internet, so you reach it through a private SSH tunnel from your own computer. This guide walks through the whole connection, from the server to your browser.

How the connection works

DatabasePostgres in Docker on the server
Studio servercrm_drizzle_studio on 127.0.0.1:4983, server only
SSH tunnelCarries port 4983 to your computer
Your browserStudio page talks to localhost:4983
  • The Studio container uses the same database login as the backend. You never type a database password.
  • Port 4983 is bound to the server itself, so there is no public address and no AWS security group rule for it.
  • The SSH tunnel uses your server key. Only someone who can SSH into the server can open Studio.
Why not a normal web address?The Studio page can only connect to a plain host and port. It cannot send your owner login, so a public Studio address would let anyone on the internet edit the database.

Before you start

  • The server’s key file (.pem) on your computer, the same one you use to SSH into the server.
  • The server address. The login user is ec2-user. This guide writes the address as YOUR-SERVER.
  • Chrome or Firefox. Safari and Brave block the connection to localhost.
  • A terminal: Terminal on macOS, PowerShell or Windows Terminal on Windows.

1Start Studio on the server

Run on the server

Studio starts with the rest of the stack. After pulling new code, rebuild and start everything from the project folder:

cd RMC
git pull
docker compose up -d --build

Check that Studio is running:

docker logs --tail 5 crm_drizzle_studio
ExpectedThe last line reads Drizzle Studio is up and running. It shows a link with host=0.0.0.0; ignore it and use the steps below.

You only need to do this once. The container restarts by itself when the server reboots. Then log out with exit.

2Open the SSH tunnel

Run on your own computer
  1. Open a terminal in the folder that holds your key file.
  2. The first time only, make the key private. SSH refuses keys that other users can read: 
    chmod 400 your-key.pem
  3. Open the tunnel. Replace your-key.pem and YOUR-SERVER: 
    ssh -i your-key.pem -N -L 4983:127.0.0.1:4983 ec2-user@YOUR-SERVER
ExpectedThe command prints nothing and keeps running. That means the tunnel is open. Leave this terminal open the whole time you use Studio.

What each part means

PartMeaning
-i your-key.pemThe key that signs you in. It must come right after -i.
-NOpen the tunnel only; don’t start a shell on the server.
-L 4983:127.0.0.1:4983Port 4983 on your computer goes to port 4983 on the server.
ec2-user@YOUR-SERVERThe server login and address.
First connectionSSH may ask Are you sure you want to continue connecting? for a new address. Type yes.

3Allow local network access

In Chrome, once per site

Recent Chrome versions ask before a website may reach your own computer. Without this, Studio shows “Recent Chrome/Chromium updates may block local network access by default.”

  1. Open https://local.drizzle.studio.
  2. Click the icon to the left of the address bar, then Site settings.
  3. Set Apps on device (also called Local network access) to Allow.
  4. Go back and reload the page.

To use Studio inside the dashboard, repeat the same steps on the dashboard site.

4Open Studio

In your browser

Inside the owner dashboard

  1. Open Settings → Engineering, then the Drizzle Studio tab.
  2. Studio loads inside the page. If the tab shows Connect to Drizzle Studio, check the tunnel and click Reconnect.
  3. Click Open in new tab for a full-screen view.

Directly

Go to https://local.drizzle.studio. With the tunnel open it connects straight away.

ConnectedThe table list appears on the left. Pick a table to browse, filter, sort, edit or add rows.

5Disconnect

In the tunnel terminal press Ctrl + C. Studio stops working in your browser right away. Studio keeps running on the server, so next time you only repeat step 2 and step 4.

Use a different database

Run on the server

By default Studio opens the stack’s own Postgres. To point it somewhere else, create a .env file next to docker-compose.yml:

STUDIO_DB_HOST=postgres
STUDIO_DB_PORT=5432
STUDIO_DB_USER=crm_user
STUDIO_DB_PASSWORD=your-password
STUDIO_DB_NAME=crm_db

Then restart Studio:

docker compose up -d drizzle-studio
Keep it on the serverNever commit this .env file or paste passwords into the docs.

Troubleshooting

You seeFix
Permission denied (publickey,gssapi-keyex,gssapi-with-mic)The key is missing. Add -i your-key.pem right after ssh.
Bad local forwarding specification 'your-key.pem'The key file was put after -L. Use -i your-key.pem, and keep -L 4983:127.0.0.1:4983 as its own part.
WARNING: UNPROTECTED PRIVATE KEY FILE!Run chmod 400 your-key.pem once, then retry.
bind [127.0.0.1]:4983: Address already in useAnother tunnel or Studio already uses port 4983. Close it, or use -L 4984:127.0.0.1:4983 and open https://local.drizzle.studio?port=4984.
“Recent Chrome/Chromium updates may block local network access”Do step 3: allow Apps on device for the site.
Studio keeps saying it is connecting to localhost:4983Check the tunnel terminal is still open. If it is, SSH into the server and run docker logs --tail 20 crm_drizzle_studio.
The dashboard tab shows Connect to Drizzle StudioOpen the tunnel, then click Reconnect.
Blank page in Safari or BraveUse Chrome or Firefox, or turn off Brave Shields for the site.

Safety rules

  • Every edit saves straight to the live database. There is no undo; the nightly backup is the only way back.
  • Never publish port 4983 or add a security group rule for it. The tunnel is the only safe way in.
  • Keep the key file private and never commit it to the repository.
  • Close the tunnel when you are finished.
